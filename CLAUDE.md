# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A multi-user PSX (Pakistan Stock Exchange) portfolio ledger and monthly SIP (systematic investment plan) planner, built with Next.js App Router code executed by **vinext** (a Next.js-compatible runtime built on Vite + React Server Components), deployed as a **Cloudflare Worker** in the owner's own Cloudflare account, with a **D1** (SQLite) database via Drizzle ORM. Auth is Google OAuth sign-in (any verified Google account by default; `ALLOWED_EMAILS` can optionally restrict it to a list again), not a custom accounts system — every user's data is isolated by their email as the primary key. **The portfolio is end-to-end encrypted:** the client encrypts it (AES-256-GCM, data key wrapped by an Argon2id vault password and a recovery key) and the server stores ciphertext only in a separate D1 database, `VAULT_DB`. Read the "Private by design" section of `README.md` and `docs/private-portfolio-encryption-progress.md` before touching portfolio storage, the API routes, scrapers, AI or push.

Full product/domain rules (cost-basis accounting, SIP allocation limits, calculation boundaries) are documented in `README.md` — read it before changing any portfolio math, allocation logic or Monthly Picks behavior. Do not duplicate that reasoning here.

## Commands

- `npm run dev` — start the vinext/Vite dev server (Cloudflare Worker emulation via `@cloudflare/vite-plugin` + Miniflare).
- `npm run db:migrate:local` — apply D1 migrations locally (`--local --persist-to .wrangler/state`). Run once before first local `dev`.
- `npm run db:generate` — generate a new Drizzle migration from `db/schema.ts` changes (migrations are append-only; do not edit past migration files).
- `node --test tests/portfolio.test.mjs` — run a single test file directly (all `tests/*.test.mjs` are plain `node:test` files, no test runner config needed). `node --test 'tests/*.test.mjs'` runs the whole suite — a bare `node --test tests/` (no glob) fails with `MODULE_NOT_FOUND` on this project's Node version.
- `npx tsc --noEmit` — type check.
- `npm run build` — production build to a Cloudflare Worker (`dist/`).
- `npm run start` — run the built Worker with `wrangler dev`.
- `npm run lint` / `npm run format` — oxlint / oxfmt.
- `npm run quote-refresh:dev` — run the separate PSX-refresh Worker locally (`workers/quote-refresh/`), with `--test-scheduled` so its cron handler can be triggered manually via `/__scheduled`.
- `npm run quote-refresh:deploy` — deploy the PSX-refresh Worker (its own Cron Trigger schedule, same D1 database).
- `npm run build:staging` / `npm run deploy:staging` / `npm run db:migrate:staging` — build (`CLOUDFLARE_ENV=staging`), deploy and migrate the **staging** Worker + D1 database (see Staging below). Normally CI does this (`.github/workflows/deploy-staging.yml`); `D1_DATABASE_ID=<staging id> node scripts/seed-staging.mjs --dry-run` previews the fictional staging seed (refuses to run against the production id).
- `node scripts/psx-history-scrape.mjs --dry-run --tickers=MEBL,LUCK` — GitHub Actions scraper (`.github/workflows/psx-history.yml`) that fills `price_history` (daily closes + today's ticks) from PSX `/timeseries/{eod,int}/<T>`, which needs the AJAX headers + page token (`lib/psx-fetch.ts#fetchPsxTimeseries`); `/api/price-history?ticker=` serves it to the company chart.
- `node scripts/psx-facts-scrape.mjs --dry-run --tickers=MEBL,LUCK` — GitHub Actions scraper (`.github/workflows/psx-facts.yml`, daily 17:00 PKT + on-demand `workflow_dispatch` with a `tickers` input) that fills `company_facts` from PSX company pages. Monthly Picks reads only this cache — the Worker never fetches PSX company pages (PSX answers Cloudflare egress with 520). Needs `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN` to write.
- `node scripts/psx-payout-scrape.mjs --dry-run --tickers=MEBL,LUCK` — run the GitHub Actions PSX dividend-announcement scraper locally without writing (`.github/workflows/psx-payouts.yml`; feeds `dividend_announcements`, which `lib/portfolio.ts#pendingAutoDividends` turns into `source: 'auto'` dividends on dashboard load).
- `node scripts/psx-ipo-scrape.mjs --dry-run --tickers=JSRR` — look up official IPO offer evidence for symbols from PSX's IPO pages (`.github/workflows/psx-ipo.yml`, on-demand only; writes `ipo_offers`).
- `node scripts/psx-quote-scrape.mjs --dry-run --tickers=MEBL,LUCK` — run the GitHub Actions PSX scraper locally without writing (PSX blocks Cloudflare egress, so `.github/workflows/psx-quotes.yml` is the primary live-price source; it needs `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN` to write).

## Architecture

**Routing/runtime**: `next.config.ts` exists but the app runs under `vinext`, not `next`. `app/layout.tsx` + `app/page.tsx` follow Next.js App Router conventions and Next APIs work as usual (`next/headers`, `next/navigation`, `next/font/google`). `app/page.tsx` currently mounts a single client component (`Dashboard` from `app/portfolio.tsx`) with in-app tab state — tabs map to paths via `TAB_PATHS` in `app/portfolio.tsx`, and `/company/<TICKER>` (`app/company/[ticker]/page.tsx`) opens the per-company page (`app/company-detail.tsx`: cards, price chart, ledger, dividends) inside the same `Dashboard`. The Activity tab (`/activity`, with `/history` kept as an alias) renders `app/ledger-timeline.tsx`. Auth-related paths (`/api/auth/google/login`, `/api/auth/google/callback`, `/api/auth/logout`) are reserved by `lib/auth.ts` — don't repurpose these path names for app routes.

**Auth**: `lib/auth.ts#getCurrentUser()` verifies a stateless, HMAC-signed session cookie (`lib/session.ts`) set by the Google OAuth flow (`app/api/auth/google/{login,callback}/route.ts`), optionally checking the signed-in email against `ALLOWED_EMAILS` (empty = open to any verified Google account). `lib/server.ts#identity()` wraps this for API routes and also enforces same-origin on writes.

**Vault / privacy boundary**: `lib/vault-crypto.ts` (primitives, AAD, Argon2id; `@noble/*` pinned exact), `lib/vault-client.ts` (`VaultSession`: setup, unlock, recover, save, backup), `lib/portfolio-view.ts` (decrypt + overlay public data), `lib/vault-store.ts`/`lib/vault-api.ts` (server, ciphertext only, `vaultDb()` binding `VAULT_DB`, migrations in `drizzle-vault/`). Endpoints: `/api/vault`, `/api/v3/portfolio` (old `/api/portfolio` returns 426), `/api/public-data?tickers=`. The server, scrapers and Workers must never receive holdings, budgets, notes, shortlists or picks results: scrapers use public tickers (`scripts/d1-rest.mjs#trackedTickers`), push is generic (`lib/dividend-push.ts`), no AI call gets private data (`tests/privacy-boundary.test.mjs` guards this). Web: `app/vault-gate.tsx`, `app/vault-security.tsx`, `app/vault-transport.ts`. Mobile: `mobile/src/vault/` (needs `expo-crypto`, i.e. a native build). Shared modules the phone imports are listed in `tests/shared-lib.test.mjs`. Monthly Picks run on the device (`lib/picks-run.ts`, `lib/picks-local.ts`, `lib/public-analysis.ts`); there is no server run engine, no AI ranking and no AI review. Release tooling: `docs/private-portfolio-release-runbook.md`, `scripts/reset-legacy-private-data.mjs` (dry-run by default, never run it against production without the runbook), `scripts/ensure-vault-db.mjs`. `deploy.yml` deploys nothing while the production `VAULT_DB` id in `wrangler.jsonc` is the zeros placeholder.

**Other assets (gold and silver; plan in the project files `plans/other-assets.md`)**: `Portfolio.assets` (`lib/assets.ts`, optional, inside the encrypted ledger) holds coins and bars as dated buy/sell/opening entries; `valueMetal` values them on the device from public rates (`lib/metal-rates.ts`: local dealer rate if at most 2 days old, else international spot converted to rupees). Rates live in the shared `metal_rates` table, written by `scripts/metal-rates-scrape.mjs` (`metal-rates.yml`) and served without parameters by `/api/public-data/metals`; the server never learns holdings. `lib/account-overview.ts` builds the All dashboard (net worth, asset mix, per-portfolio shares, income, return) and includes gold and silver; `lib/plans.ts` adds savings plans (Pak-Qatar Mahana Bachat): value comes from a dated statement value you enter, shown as an estimate between statements, gains stay in the plan, redeemed cash is an entry, and monthly contributions come due as expected entries to confirm or skip. `valueAsset` reduces every asset to class/value/cost/flows for the overview; mutual funds (`lib/funds.ts`, `lib/mufap.ts`) are valued as units × MUFAP repurchase price (a newer manual price wins); cash dividends are income, reinvested ones add units. Fund names and NAVs are public (MUFAP blocks GitHub's runners with 403 but answers Cloudflare, so `lib/mufap-refresh.ts` runs in the quote-refresh cron Worker daily and from the super-admin `POST /api/admin/refresh-funds`; `scripts/mufap-nav-scrape.mjs` is a manual fallback): `scripts/mufap-nav-scrape.mjs` (`mufap-navs.yml`, refuses to write if fewer than 50 funds parse) fills `fund_catalog`/`fund_navs`, served by `/api/public-data/funds` (`?fund=<id>` for one fund's history). The phone shows gold, plans and funds read-only.

**Usage analytics (plan in the project files `plans/analytics.md`)**: first-party events in the main D1 (never `VAULT_DB`): `app_users` (written at sign-in; `origin` starts `unknown` and `lib/analytics-store.ts#resolveOrigin` settles it from the `account_state` event the clients send once per session (the server never reads the vault database for analytics)), `analytics_events` (user key = HMAC of the email, 180-day retention). The catalog `lib/analytics-events.ts` is the privacy boundary: event names and closed-enum props only, no free text; `POST /api/events` rejects anything else. Clients call `track()` (`app/analytics.ts`, `mobile/src/analytics/analytics.ts`); saves become events through `lib/analytics-diff.ts`. Opt-out is a per-device switch (Settings / More), on by default. Dashboard: Settings > Usage analytics (super admin, web only) from `GET /api/admin/usage`. Cloudflare Web Analytics loads only on the signed-out landing, privacy and terms pages and only when the `CF_WEB_ANALYTICS_TOKEN` var is set. Tests: `tests/analytics.test.mjs`. When adding an event, add it to the catalog, never add a prop that could hold a ticker, amount or name.

**Themes**: four web themes (Light is the default, Dark, Midnight, Paper) plus System. The active theme is `html[data-theme]`, set before first paint by the inline script from `lib/theme.ts#themeInitScript` (in `app/layout.tsx`) and changed by `app/use-theme.ts` (account menu and Settings > Appearance via `app/theme-menu.tsx`). The choice lives in localStorage (`sipwise.theme`) only, never in the vault or on the server. `app/globals.css` has one token block per theme (`tests/theme.test.mjs` checks they stay complete). Never write hex or rgba literals in app CSS or chart code: use the tokens (`var(--primary)`, `rgb(var(--ch-primary) / .16)`, `--cat-1..7` for charts, `--soft-ink`, `--warn-ink` and so on). The `.accent` and `.research-hero` slabs stay dark in every theme on purpose. Mobile has its own theme code.

**Roles**: `user_roles` (email → `super_admin` | `user`; no row = `user`; seeded in migration `0016` with the owner as `super_admin`) is read by `lib/roles.ts#getUserRole`. `lib/auth.ts#getViewer()` returns the user plus role and Google `picture` (carried in the signed session cookie; only `https://*.googleusercontent.com` URLs are accepted in the OAuth callback). The Research desk (tab, `/research-desk` page redirect, Settings "Research AI" section) is super-admin only, and every `app/api/research/*` route is guarded server-side by `lib/server.ts#requireSuperAdmin` (403 otherwise). Grant roles by inserting into `user_roles`.

**Notifications**: clearing from the bell sets `clearedAt` on the notification instead of deleting it, so it stays in the `/notifications` history page (`app/notifications-view.tsx`) and still de-dupes new announcements. "Delete cleared" there is the only permanent removal.

**Data layer**: `db/schema.ts` defines D1 tables via Drizzle (legacy plaintext `portfolios`/`ai_reviews`/`monthly_recommendations`/`recommendation_attempts` are no longer read or written and are cleared by the reset tool; `research_jobs`, `research_events`, `research_helpers`, `quote_refreshes`, `company_facts`, `price_history`, `ai_usage`). `db/index.ts` wires up the Drizzle client; `lib/server.ts#db()` fetches the D1 binding from `cloudflare:workers` `env.DB`. Portfolio state lives in `VAULT_DB` as one ciphertext envelope per user with a `revision` counter used for optimistic-concurrency (stale-write rejection); the decrypted shape and calculation logic are in `lib/portfolio.ts`, and `lib/portfolio-reports.ts` for report generation. `company_facts` is a shared (not per-user) cache of parsed PSX company-page data, one row per ticker holding the latest scrape (`fetched_on` = PKT day; treated as fresh for 7 days), written only by `scripts/psx-facts-scrape.mjs`; `facts_requests` tracks on-demand scrape requests/attempts/errors per ticker — see `lib/company-facts.ts`/`lib/company-facts-store.ts` and the Monthly Picks research section below.

**API routes** (`app/api/**/route.ts`): `vault` + `v3/portfolio` (encrypted ledger; `portfolio` returns 426), `public-data`, `quotes` (PSX price cache), `recommendations` (public analysis for client-named tickers via `GET ?tickers=`; `POST {action:'refresh-facts',tickers}` dispatches an on-demand facts scrape via `lib/github-dispatch.ts`: Worker secret `GITHUB_DISPATCH_TOKEN`, var `GITHUB_REPO`; ranking and sizing happen on the client), `research/*` (admin research jobs on public company data, the in-browser runner `research/run`, the `research/proxy` fetch proxy, and synthesis; results are applied to the encrypted portfolio on the client).

**Monthly Picks execution**: on the device (`lib/picks-run.ts`, `lib/picks-local.ts`); finished runs are stored in the encrypted portfolio as `monthlyPicksRuns`. Limits (35% per pick, 20% concentration) are applied in `lib/monthly-picks-allocation.ts`. The server only serves public analysis (`lib/public-analysis.ts`). Status and open items: `docs/private-portfolio-encryption-progress.md`.

**Main UI** (`app/portfolio.tsx`, ~1600 lines): holds nearly all dashboard state via `useState` (portfolio data, active tab, trade/edit dialogs, quote entry; wrapped by the vault gate) and renders a shadcn `Tabs` (`components/ui/tabs`) with six panels: Holdings, Reports, Monthly SIP, Activity, Research desk, AI review. `app/research-desk.tsx` and `app/dossier-experience.tsx` / `app/original-dossier.tsx` implement the research/dossier sub-experience embedded in the "Research desk" tab. `app/portfolio-reports.tsx` renders the Reports tab.

**Research desk background jobs**: research jobs (`research_jobs`/`research_events` tables) are processed entirely by an in-browser runner (`app/research-runner.ts`), not a separate process — while a Research desk tab is open, it claims the signed-in user's queued jobs via `app/api/research/run/route.ts` (session-authed, lease/checkpoint based so any open tab on any device can resume a job), fetches PSX/issuer/search pages through `app/api/research/proxy/route.ts` (CORS workaround, with SSRF-conscious host checks in `lib/research-policy.mjs`), extracts PDF text client-side with `pdfjs-dist` (`app/research-pdf.ts`), and requests AI synthesis (`app/api/research/synthesize/route.ts`). There is no separate CLI or native binary dependency.

**workers/quote-refresh/**: a second, independent Cloudflare Worker (own `wrangler.jsonc`, own Cron Trigger every 15 min 04:00–11:45 UTC Mon–Fri = 09:00–16:45 PKT) that refreshes stale PSX quotes (stalest first, fetch-budgeted) for the tickers clients have already named (the public `quote_refreshes` table; it has no private database binding) into the shared `quote_refreshes` table via `lib/quote-cache.ts#refreshQuotes` — the same cache path `/api/quotes` and `/api/market-summary` use. It is separate from the main Worker because `vinext`'s generated entry only exports a `fetch` handler, not `scheduled`. The client merges `quote_refreshes` into its decrypted portfolio newest-wins (`lib/quote-merge.ts`, `lib/portfolio-view.ts`), skipping any ticker the user has manually verified.

**Company directory / face values / quote jobs**: `security_catalog` is the shared company master (names, sectors, per-field sources, status), filled by `scripts/psx-directory-scrape.mjs` (`psx-directory.yml`; logic in `lib/company-directory*.ts`) and read through `lib/company-resolver.ts` / `/api/companies`; `PUT /api/portfolio` with `createCompanies` is strict, other saves repair placeholders (`lib/company-save.ts`). Dated face-value evidence lives in `security_face_values` (`lib/face-values.ts`, `psx-face-values.yml`, `/api/face-values`); there is no silent Rs 10 default. Manual price refresh is a queued job: `/api/quotes` serves the cache and queues `quotes` rows in `refresh_requests`, `scripts/psx-quote-scrape.mjs` completes them with verified outcomes (`lib/quote-jobs.ts`, `lib/quote-scrape-run.ts`); Cloudflare never fetches PSX prices. Progress and open items: `docs/psx-company-directory-dashboard-progress.md`.

**AHL statement import / historical dividends**: `lib/ahl-ledger-pdf.ts` (parser), `lib/ahl-reconcile.ts` (preview plan + apply), `lib/ipo-offers.ts` / `lib/ipo-evidence.ts` (assumed-acquisition pricing, curated and scraped IPO evidence), `lib/dividend-history.ts` (historical candidates and approve-as-received), `lib/workflow-requests.ts` + `lib/refresh-api.ts` (per-company on-demand GitHub fetch state in `refresh_requests`, used by `app/api/dividends/refresh` and `app/api/ipo-offers`), `lib/psx-confirmation.ts` reads the PSX "Statement of Account / Client Confirmation" PDF used by Youngs Capital, Syed Faraz Equities and other brokers on that template into a `BrokerStatement` (`parsePsxLedger` reads the same software's full Statement of Account ledger: BUY/SELL narrations plus the Inventory Position as holdings; fills only, fees = net amount minus gross; no name, address or bank data read), reviewed in the generic `app/broker-import-dialog.tsx` with `source: 'broker'` (`tests/psx-confirmation.test.mjs`; set `YOUNGS_LOCAL_PDF`/`SFEL_LOCAL_PDF` to check real files locally), UI in `app/ahl-import-dialog.tsx` and `app/dividend-sync-view.tsx`. Historical calendar helpers in `lib/psx-calendar.ts` (`executionDateFromSettlement`, `historicalEntitlement`) are separate from the live-market `isTradingDay`. Tests build synthetic PDFs (`tests/helpers/ahl-ledger-fixture.mjs`) and run them through the browser extraction path; `tests/ahl-ledger-pdf.test.mjs` also checks a real statement when the `AHL_LOCAL_PDF` env var points at one and is skipped otherwise. Never commit a real statement. pdf.js text extraction fails in `npm run dev` ("window is not defined" from the Vite worker); verify PDF imports against `npm run build` + `npm run start`.

**AI Lab (experimental, super admin only)**: `app/ai-lab.tsx` (+ `ai-lab-holdings.tsx`, `use-ai-lab.ts`, route `/ai-lab`) is a separate tab; Monthly Picks is unchanged. Research runs only in GitHub Actions (`scripts/ai-research.mjs`, `ai-research.yml`, `ai-research-staging.yml`) via `lib/ai-research/*` (provider adapters for OpenAI/Anthropic, spend ledger (no cap unless `AI_RESEARCH_MONTHLY_CAP_USD` is set), reuse rules, fact pack, code-side verification) into shared tables `ai_research_runs`, `ai_macro_briefs`, `ai_company_profiles`, `ai_financial_extracts`, `ai_news_items`, `ai_company_research`, `ai_rankings`, `ai_research_requests` (all public data, listed in `SHARED_TABLES`). `app/api/ai-lab/research` (super-admin) reads results and queues requests. Ranking, sizing and holdings review run on the device (`lib/ai-lab-picks.ts`, `lib/holdings-review.ts`); the AI never receives holdings or amounts, and `tests/ai-lab.test.mjs` guards that boundary. Env: `AI_LAB_ENABLED`, `AI_RESEARCH_MONTHLY_CAP_USD`, `OPENAI_API_KEY` (and Anthropic key if switched) as GitHub secrets. Plan: `docs/ai-lab-progress.md`.

**Staging**: `wrangler.jsonc` has an `env.staging` block (Worker `psx-portfolio-sip-staging`, its own D1 database `psx_portfolio_sip_staging`, `ALLOWED_EMAILS` = owner only, its own `VAULT_DB` (`psx_portfolio_sip_staging_vault`, created by `scripts/ensure-vault-db.mjs`), `APP_ENV=staging`; wrangler envs don't inherit vars/bindings, so they are repeated there). `CLOUDFLARE_ENV=staging npm run build` makes `@cloudflare/vite-plugin` write the flattened staging config to `dist/server/wrangler.json` (verified with vinext); migrate with `wrangler d1 migrations apply DB --remote --env staging`. `deploy-staging.yml` deploys every same-repo PR to `main` (and manual runs) using the `staging` GitHub environment, and skips cleanly while the staging `database_id` is still the all-zeros placeholder. The quote-refresh cron Worker and `GITHUB_DISPATCH_TOKEN` are not set up on staging, and production user data is never copied: `seed-staging.yml` runs the PSX scrapers (`D1_DATABASE_ID` read from `env.staging` in `wrangler.jsonc`, via `scripts/d1-rest.mjs`) and `scripts/seed-staging.mjs`, which only writes a fictional plain ledger backup file to import through the app; `reset-staging.yml` wipes the staging DB (`scripts/reset-staging.mjs`), re-migrates and re-seeds. Seed/reset scripts refuse to run when `D1_DATABASE_ID` is unset or equals the production id. `APP_ENV=staging` puts a STAGING badge on the app bar (`html[data-app-env]` set in `app/layout.tsx`, styled in `globals.css`). `DEV_AUTH_EMAIL` stays loopback-only and is never set on staging. One-time owner setup: (1) `npx wrangler d1 create psx_portfolio_sip_staging`, paste the printed `database_id` into `env.staging` in `wrangler.jsonc`; (2) add `https://psx-portfolio-sip-staging.<subdomain>.workers.dev/api/auth/google/callback` as an authorized redirect URI on the Google OAuth client; (3) create the GitHub `staging` environment with secrets `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN`; (4) after the first staging deploy, `npx wrangler secret put SESSION_SECRET|GOOGLE_CLIENT_SECRET|OPENAI_API_KEY --env staging` (use a different `SESSION_SECRET` from prod); (5) run the Seed staging workflow.

**Testing**: no test framework/config — `tests/*.test.mjs` use Node's built-in `node:test` + `node:assert`, run individually or via `node --test 'tests/*.test.mjs'`. Tests cover calculation logic (`lib/portfolio.ts`, `lib/portfolio-reports.ts`), research policy/evidence logic, and session cookie signing/verification (`lib/session.ts`), not UI.

## Conventions

- Path alias `@/*` maps to the project root (see `tsconfig.json`) — e.g. `@/lib/portfolio`, `@/components/ui/tabs`.
- oxlint runs with `typeAware`/`typeCheck` on and treats the `correctness` category as errors; `no-explicit-any`, `no-deprecated`, and `react/rules-of-hooks` are enforced.
- Local dev auth bypass: `lib/auth.ts#getCurrentUser()` returns a fixed user when `env.DEV_AUTH_EMAIL` is set **and** the request `Host` is loopback (`localhost`/`127.0.0.1`/`[::1]`). Set it in a git-ignored `.dev.vars`; never add it to `wrangler.jsonc` `vars` or `wrangler secret put` it. Keep both guards if you touch this function.
- `.env.local` is git-ignored; `OPENAI_API_KEY`, `GOOGLE_CLIENT_SECRET`, and `SESSION_SECRET` are server-only secrets (never exposed client-side or committed) — set them with `wrangler secret put <NAME>` for the deployed Worker.
