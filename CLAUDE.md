# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A multi-user PSX (Pakistan Stock Exchange) portfolio ledger and monthly SIP (systematic investment plan) planner, built with Next.js App Router code executed by **vinext** (a Next.js-compatible runtime built on Vite + React Server Components), deployed as a **Cloudflare Worker** in the owner's own Cloudflare account, with a **D1** (SQLite) database via Drizzle ORM. Auth is Google OAuth sign-in (any verified Google account by default; `ALLOWED_EMAILS` can optionally restrict it to a list again), not a custom accounts system — every user's data is isolated by their email as the primary key.

Full product/domain rules (cost-basis accounting, SIP allocation limits, AI review scope, calculation boundaries) are documented in `README.md` — read it before changing any portfolio math, allocation logic, or AI review behavior. Do not duplicate that reasoning here.

## Commands

- `npm run dev` — start the vinext/Vite dev server (Cloudflare Worker emulation via `@cloudflare/vite-plugin` + Miniflare).
- `npm run db:migrate:local` — apply D1 migrations locally (`--local --persist-to .wrangler/state`). Run once before first local `dev`.
- `npm run db:generate` — generate a new Drizzle migration from `db/schema.ts` changes (migrations are append-only; do not edit past migration files).
- `node --test tests/portfolio.test.mjs` — run a single test file directly (all `tests/*.test.mjs` are plain `node:test` files, no test runner config needed). `node --test 'tests/*.test.mjs'` runs the whole suite — a bare `node --test tests/` (no glob) fails with `MODULE_NOT_FOUND` on this project's Node version.
- `npx tsc --noEmit` — type check.
- `npm run build` — production build to a Cloudflare Worker (`dist/`).
- `npm run start` — run the built Worker with `wrangler dev`.
- `npm run lint` / `npm run format` — oxlint / oxfmt.
- `npm run quote-refresh:dev` — run the separate PSX-refresh Worker locally (`workers/quote-refresh/`), with `--test-scheduled` so its cron handler can be triggered manually via `/__scheduled`.
- `npm run quote-refresh:deploy` — deploy the PSX-refresh Worker (its own Cron Trigger schedule, same D1 database).
- `npm run build:staging` / `npm run deploy:staging` / `npm run db:migrate:staging` — build (`CLOUDFLARE_ENV=staging`), deploy and migrate the **staging** Worker + D1 database (see Staging below). Normally CI does this (`.github/workflows/deploy-staging.yml`); `D1_DATABASE_ID=<staging id> node scripts/seed-staging.mjs --dry-run` previews the fictional staging seed (refuses to run against the production id).
- `node scripts/psx-history-scrape.mjs --dry-run --tickers=MEBL,LUCK` — GitHub Actions scraper (`.github/workflows/psx-history.yml`) that fills `price_history` (daily closes + today's ticks) from PSX `/timeseries/{eod,int}/<T>`, which needs the AJAX headers + page token (`lib/psx-fetch.ts#fetchPsxTimeseries`); `/api/price-history?ticker=` serves it to the company chart.
- `node scripts/psx-facts-scrape.mjs --dry-run --tickers=MEBL,LUCK` — GitHub Actions scraper (`.github/workflows/psx-facts.yml`, daily 17:00 PKT + on-demand `workflow_dispatch` with a `tickers` input) that fills `company_facts` from PSX company pages. Monthly Picks reads only this cache — the Worker never fetches PSX company pages (PSX answers Cloudflare egress with 520). Needs `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN` to write.
- `node scripts/psx-payout-scrape.mjs --dry-run --tickers=MEBL,LUCK` — run the GitHub Actions PSX dividend-announcement scraper locally without writing (`.github/workflows/psx-payouts.yml`; feeds `dividend_announcements`, which `lib/portfolio.ts#pendingAutoDividends` turns into `source: 'auto'` dividends on dashboard load).
- `node scripts/psx-ipo-scrape.mjs --dry-run --tickers=JSRR` — look up official IPO offer evidence for symbols from PSX's IPO pages (`.github/workflows/psx-ipo.yml`, on-demand only; writes `ipo_offers`).
- `node scripts/psx-quote-scrape.mjs --dry-run --tickers=MEBL,LUCK` — run the GitHub Actions PSX scraper locally without writing (PSX blocks Cloudflare egress, so `.github/workflows/psx-quotes.yml` is the primary live-price source; it needs `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN` to write).

## Architecture

**Routing/runtime**: `next.config.ts` exists but the app runs under `vinext`, not `next`. `app/layout.tsx` + `app/page.tsx` follow Next.js App Router conventions and Next APIs work as usual (`next/headers`, `next/navigation`, `next/font/google`). `app/page.tsx` currently mounts a single client component (`Dashboard` from `app/portfolio.tsx`) with in-app tab state — tabs map to paths via `TAB_PATHS` in `app/portfolio.tsx`, and `/company/<TICKER>` (`app/company/[ticker]/page.tsx`) opens the per-company page (`app/company-detail.tsx`: cards, price chart, ledger, dividends) inside the same `Dashboard`. The Activity tab (`/activity`, with `/history` kept as an alias) renders `app/ledger-timeline.tsx`. Auth-related paths (`/api/auth/google/login`, `/api/auth/google/callback`, `/api/auth/logout`) are reserved by `lib/auth.ts` — don't repurpose these path names for app routes.

**Auth**: `lib/auth.ts#getCurrentUser()` verifies a stateless, HMAC-signed session cookie (`lib/session.ts`) set by the Google OAuth flow (`app/api/auth/google/{login,callback}/route.ts`), optionally checking the signed-in email against `ALLOWED_EMAILS` (empty = open to any verified Google account). `lib/server.ts#identity()` wraps this for API routes and also enforces same-origin on writes.

**Roles**: `user_roles` (email → `super_admin` | `user`; no row = `user`; seeded in migration `0016` with the owner as `super_admin`) is read by `lib/roles.ts#getUserRole`. `lib/auth.ts#getViewer()` returns the user plus role and Google `picture` (carried in the signed session cookie; only `https://*.googleusercontent.com` URLs are accepted in the OAuth callback). The Research desk (tab, `/research-desk` page redirect, Settings "Research AI" section) is super-admin only, and every `app/api/research/*` route is guarded server-side by `lib/server.ts#requireSuperAdmin` (403 otherwise). Grant roles by inserting into `user_roles`.

**Notifications**: clearing from the bell sets `clearedAt` on the notification instead of deleting it, so it stays in the `/notifications` history page (`app/notifications-view.tsx`) and still de-dupes new announcements. "Delete cleared" there is the only permanent removal.

**Data layer**: `db/schema.ts` defines D1 tables via Drizzle (`portfolios`, `ai_reviews`, `research_jobs`, `research_events`, `research_helpers`, `quote_refreshes`, `company_facts`, `monthly_recommendations`, `price_history`, `recommendation_attempts`, `ai_usage`). `db/index.ts` wires up the Drizzle client; `lib/server.ts#db()` fetches the D1 binding from `cloudflare:workers` `env.DB`. Portfolio state is stored as a single JSON `payload` per user with a `revision` counter used for optimistic-concurrency (stale-write rejection) — see `lib/portfolio.ts` for the shape and calculation logic, and `lib/portfolio-reports.ts` for report generation. `company_facts` is a shared (not per-user) cache of parsed PSX company-page data, one row per ticker holding the latest scrape (`fetched_on` = PKT day; treated as fresh for 7 days), written only by `scripts/psx-facts-scrape.mjs`; `facts_requests` tracks on-demand scrape requests/attempts/errors per ticker — see `lib/company-facts.ts`/`lib/company-facts-store.ts` and the Monthly Picks research section below.

**API routes** (`app/api/**/route.ts`): `portfolio` (load/save ledger), `quotes` (PSX price refresh), `review` (low-cost `gpt-5-nano` AI review, cached in `ai_reviews` by user+revision+month), `recommendations` (Monthly Picks: explicit run state machine `gathering → in_progress → completed|failed`, advanced idempotently by each `GET ?id=` poll. `gathering` waits for the on-demand facts scrape dispatched via `lib/github-dispatch.ts` (Worker secret `GITHUB_DISPATCH_TOKEN`, fine-grained PAT with Actions read/write on this repo; var `GITHUB_REPO`; unset = no on-demand fetch, run uses the daily-scraped cache); decision logic is pure in `lib/monthly-picks-flow.ts`. Then one-call AI ranking or quant fallback. `POST {action:'refresh-facts'}` requests a scrape without starting a run), `research/*` (background research jobs, an in-browser research runner surface at `research/run`, a `research/proxy` fetch proxy for sites that don't send CORS headers, and synthesis).

**Monthly Picks execution**: `lib/recommendation-service.ts` owns run state (lease-guarded steps, idempotent start, watchdog). The `workers/quote-refresh` every-minute cron calls `processDueRuns`; with `PICKS_BACKGROUND=true` GET `/api/recommendations` is read-only, otherwise it nudges the run under the same lease. Limits (35% per pick, 20% concentration) are applied in `lib/monthly-picks-allocation.ts` when a run finishes. Status and open items: `docs/monthly-picks-market-data-progress.md`.

**Main UI** (`app/portfolio.tsx`, ~1600 lines): holds nearly all dashboard state via `useState` (portfolio data, active tab, trade/edit dialogs, quote entry, AI review state) and renders a shadcn `Tabs` (`components/ui/tabs`) with six panels: Holdings, Reports, Monthly SIP, Activity, Research desk, AI review. `app/research-desk.tsx` and `app/dossier-experience.tsx` / `app/original-dossier.tsx` implement the research/dossier sub-experience embedded in the "Research desk" tab. `app/portfolio-reports.tsx` renders the Reports tab.

**Research desk background jobs**: research jobs (`research_jobs`/`research_events` tables) are processed entirely by an in-browser runner (`app/research-runner.ts`), not a separate process — while a Research desk tab is open, it claims the signed-in user's queued jobs via `app/api/research/run/route.ts` (session-authed, lease/checkpoint based so any open tab on any device can resume a job), fetches PSX/issuer/search pages through `app/api/research/proxy/route.ts` (CORS workaround, with SSRF-conscious host checks in `lib/research-policy.mjs`), extracts PDF text client-side with `pdfjs-dist` (`app/research-pdf.ts`), and requests AI synthesis (`app/api/research/synthesize/route.ts`). There is no separate CLI or native binary dependency.

**workers/quote-refresh/**: a second, independent Cloudflare Worker (own `wrangler.jsonc`, own Cron Trigger every 15 min 04:00–11:45 UTC Mon–Fri = 09:00–16:45 PKT) that refreshes stale PSX quotes (stalest first, fetch-budgeted) for every ticker held across all users' portfolios into the shared `quote_refreshes` table via `lib/quote-cache.ts#refreshQuotes` — the same cache path `/api/quotes` and `/api/market-summary` use. It is separate from the main Worker because `vinext`'s generated entry only exports a `fetch` handler, not `scheduled`. `app/api/portfolio/route.ts` GET merges `quote_refreshes` into each user's response newest-wins (`mergeQuotes`; skipping any ticker the user has manually verified), so the cron never writes to `portfolios` or touches its `revision` column.

**AHL statement import / historical dividends**: `lib/ahl-ledger-pdf.ts` (parser), `lib/ahl-reconcile.ts` (preview plan + apply), `lib/ipo-offers.ts` / `lib/ipo-evidence.ts` (assumed-acquisition pricing, curated and scraped IPO evidence), `lib/dividend-history.ts` (historical candidates and approve-as-received), `lib/workflow-requests.ts` + `lib/refresh-api.ts` (per-company on-demand GitHub fetch state in `refresh_requests`, used by `app/api/dividends/refresh` and `app/api/ipo-offers`), UI in `app/ahl-import-dialog.tsx` and `app/dividend-sync-view.tsx`. Historical calendar helpers in `lib/psx-calendar.ts` (`executionDateFromSettlement`, `historicalEntitlement`) are separate from the live-market `isTradingDay`. Tests build synthetic PDFs (`tests/helpers/ahl-ledger-fixture.mjs`) and run them through the browser extraction path; `tests/ahl-ledger-pdf.test.mjs` also checks a real statement when the `AHL_LOCAL_PDF` env var points at one and is skipped otherwise. Never commit a real statement. pdf.js text extraction fails in `npm run dev` ("window is not defined" from the Vite worker); verify PDF imports against `npm run build` + `npm run start`.

**Staging**: `wrangler.jsonc` has an `env.staging` block (Worker `psx-portfolio-sip-staging`, its own D1 database `psx_portfolio_sip_staging`, `ALLOWED_EMAILS` = owner only, `AI_MONTHLY_CAP_USD` 0.25, `APP_ENV=staging`; wrangler envs don't inherit vars/bindings, so they are repeated there). `CLOUDFLARE_ENV=staging npm run build` makes `@cloudflare/vite-plugin` write the flattened staging config to `dist/server/wrangler.json` (verified with vinext); migrate with `wrangler d1 migrations apply DB --remote --env staging`. `deploy-staging.yml` deploys every same-repo PR to `main` (and manual runs) using the `staging` GitHub environment, and skips cleanly while the staging `database_id` is still the all-zeros placeholder. The quote-refresh cron Worker and `GITHUB_DISPATCH_TOKEN` are not set up on staging, and production user data is never copied: `seed-staging.yml` runs the PSX scrapers (`D1_DATABASE_ID` read from `env.staging` in `wrangler.jsonc`, via `scripts/d1-rest.mjs`) plus `scripts/seed-staging.mjs` (fictional portfolio); `reset-staging.yml` wipes the staging DB (`scripts/reset-staging.mjs`), re-migrates and re-seeds. Seed/reset scripts refuse to run when `D1_DATABASE_ID` is unset or equals the production id. `APP_ENV=staging` puts a STAGING badge on the app bar (`html[data-app-env]` set in `app/layout.tsx`, styled in `globals.css`). `DEV_AUTH_EMAIL` stays loopback-only and is never set on staging. One-time owner setup: (1) `npx wrangler d1 create psx_portfolio_sip_staging`, paste the printed `database_id` into `env.staging` in `wrangler.jsonc`; (2) add `https://psx-portfolio-sip-staging.<subdomain>.workers.dev/api/auth/google/callback` as an authorized redirect URI on the Google OAuth client; (3) create the GitHub `staging` environment with secrets `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN`; (4) after the first staging deploy, `npx wrangler secret put SESSION_SECRET|GOOGLE_CLIENT_SECRET|OPENAI_API_KEY --env staging` (use a different `SESSION_SECRET` from prod); (5) run the Seed staging workflow.

**Testing**: no test framework/config — `tests/*.test.mjs` use Node's built-in `node:test` + `node:assert`, run individually or via `node --test 'tests/*.test.mjs'`. Tests cover calculation logic (`lib/portfolio.ts`, `lib/portfolio-reports.ts`), research policy/evidence logic, and session cookie signing/verification (`lib/session.ts`), not UI.

## Conventions

- Path alias `@/*` maps to the project root (see `tsconfig.json`) — e.g. `@/lib/portfolio`, `@/components/ui/tabs`.
- oxlint runs with `typeAware`/`typeCheck` on and treats the `correctness` category as errors; `no-explicit-any`, `no-deprecated`, and `react/rules-of-hooks` are enforced.
- Local dev auth bypass: `lib/auth.ts#getCurrentUser()` returns a fixed user when `env.DEV_AUTH_EMAIL` is set **and** the request `Host` is loopback (`localhost`/`127.0.0.1`/`[::1]`). Set it in a git-ignored `.dev.vars`; never add it to `wrangler.jsonc` `vars` or `wrangler secret put` it. Keep both guards if you touch this function.
- `.env.local` is git-ignored; `OPENAI_API_KEY`, `GOOGLE_CLIENT_SECRET`, and `SESSION_SECRET` are server-only secrets (never exposed client-side or committed) — set them with `wrangler secret put <NAME>` for the deployed Worker.
