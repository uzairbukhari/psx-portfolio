# PSX Portfolio & SIP

Multi-user investment ledger with D1 persistence, official PSX quote refresh (manual and automatic twice-daily), and sourced Monthly Picks research. Any Google account can sign in; each account gets its own fully isolated portfolio, starting empty. (The original owner's account was seeded from a private CDC statement before this app became multi-user — that seed data is not applied to new accounts.)

## User workflow

1. Sign in with Google. New accounts start with an empty ledger — add holdings via recorded purchases or an imported backup.
2. Record actual purchases (ticker, date, integer shares, price, fees, optional SIP month). Correct an opening entry to add a known average cost. Corrections void the prior entry, retaining its audit record.
3. Record forward stock splits from the company history using the effective date and old/new share ratio. The preview shows the adjusted quantity and average cost before saving; corrections and voids retain the earlier event for audit.
4. PSX prices refresh automatically every 15 minutes during PKT trading hours on weekdays (see `workers/quote-refresh/`); refresh on demand with the "Refresh PSX prices" button, or enter a verified manual quote and date. Every held company and target company needs a price for a complete SIP calculation.
5. In Monthly Picks, select up to 15 saved companies, choose a month and enter fresh investment money. The shortlist is treated as user-approved eligibility.
6. Market Pulse follows that saved shortlist. It uses the owner's pyPSX live feed during estimated market hours when configured, and otherwise refreshes PSX's five-minute-delayed public data every minute while the dashboard is visible.
7. Request sourced 60–90 day research. It ranks up to five companies, proposes a rupee split, and estimates affordable whole shares from dated PSX quotes. It never records trades automatically.
8. Export a full portfolio backup periodically. This schema is distinct from the company-research dashboard's JSON import; restoring replaces only this ledger and requires confirmation.

## Calculation boundaries

Weighted average cost includes purchase fees. Sales remove shares at the average cost immediately before the sale; missing opening cost keeps cost and return unknown until that position is fully closed or corrected. Same-day entries use ledger order, with opening balances first. Earlier transactions cannot be added before an active opening snapshot; void/correct that snapshot before importing full historical transactions to avoid double-counting.

Market values exclude cash, dividends and unrecorded corporate actions. A recorded forward split multiplies only shares held before its effective date, preserves total cost, and requires a quote dated on or after the split before the holding is valued. Returns are unrealised changes in the remaining holdings, not a total-return or tax report. The estimate allocates integer shares, rounds fee-inclusive unit costs upward to the paisa and remains within the remaining monthly budget. New allocation gaps are capped using 20% of priced holdings plus the remaining contribution. There is no recommendation to sell an existing overweight position. Targets and 183-day screening expiry are editable planning assumptions, not formal Shariah certification.

## Monthly Picks research

Evidence comes from PSX itself, not from an AI web search. For each shortlisted ticker, the server fetches and parses `https://dps.psx.com.pk/company/<TICKER>` (`lib/company-facts.ts`) into price, P/E (TTM), 52-week range, four years of annual and four quarters of financials (revenue, profit after taxation, EPS), margin/growth/PEG ratios, and dated announcements — cached per ticker per PKT day (`company_facts` table) so a same-day re-run costs zero fetches. Code then computes deterministic metrics (earnings yield, EPS YoY and CAGR, net-margin trend, 52-week position, most recent announcement age) and a 0–100 quant score per company (`computeMetrics`/`quantScore`/`quantAllocation`) — no AI involvement, fully explainable, and available even if the AI step below is skipped.

One `gpt-5-mini` call (no tools, no web search) then ranks the shortlist using only these code-verified numbers as input, with the quant score as an explicit baseline it may deviate from but must justify. Its output is sanitized in code (`lib/monthly-picks-ai.ts`): unknown or duplicate tickers are dropped, allocations are renormalized so picks plus cash total 100%, and every shortlisted company gets a coverage entry. If the AI call fails, times out, or its output has nothing usable, the run falls back to `quantResult` — the same result shape built directly from the quant score, with no AI call. A run therefore always finishes as `completed` (`result.method` is `'ai'` or `'quant'`); `failed` is reserved for the case where PSX returned no usable data for any shortlisted company. Source links are attached by code from the fetched PSX page and cited announcement PDFs, not chosen by the model, so there is no citation-validation failure mode.

The AI call, when used, costs roughly $0.005–0.02 per run (a few thousand input tokens, no per-search charges), reserved against a $0.25 cap before it is sent. `recommendation_attempts` retains the request, raw response, cost, and any error for that one call. The recommendation row stores an immutable snapshot (fetched facts, computed metrics, quant scores) so a saved result is reproducible without re-fetching PSX. Runs saved by the earlier per-company-evidence workflow remain readable but are never reused as current-workflow evidence; an active row from that workflow is marked `needs_attention` on next load rather than resumed.

Production for this checkout is `https://psx-portfolio-sip.suzairbukhari.workers.dev`. The older ChatGPT Sites publication is a separate deployment, not proof that this Worker has been updated. Apply migrations through `0012_adorable_rocket_racer.sql` before deploying this version.

## Development & deployment

- Node >=22.13; install with npm and preserve package-lock.json.
- Before the first local run, execute `npm run db:migrate:local` once to create the local D1 tables. Then `npm run dev` starts the Vinext preview.
- Local sign-in bypass: put `DEV_AUTH_EMAIL=dev@localhost` (optionally `DEV_AUTH_NAME`) in a git-ignored `.dev.vars` and `npm run dev` treats every request as that user, skipping Google OAuth — no `GOOGLE_CLIENT_SECRET`/`SESSION_SECRET` needed locally. `lib/auth.ts` only honours it when the request's `Host` is `localhost`, `127.0.0.1` or `[::1]`, and `.dev.vars` is never deployed, so the deployed Worker still requires a real signed session. Change the email to switch which local portfolio row you load.
- `node --test 'tests/*.test.mjs'` runs all tests: portfolio cost accounting, sales, missing data, dates, monthly budgets, allocation limits and AI weights (`tests/portfolio.test.mjs`); PSX company-page parsing, quant metrics/scoring and allocation (`tests/company-facts.test.mjs`); Monthly Picks AI-output sanitizing and the quant fallback (`tests/monthly-picks-ai.test.mjs`); plus session cookie signing/verification (`tests/session.test.mjs`).
- `npx tsc --noEmit` checks types; `npm run build` builds the Cloudflare Worker.
- D1 schema is in `db/schema.ts`; generate append-only migrations with `npm run db:generate`. Apply local migrations with `--local --persist-to .wrangler/state`; apply them to your own deployed database with `wrangler d1 migrations apply DB --remote`.
- This is a standalone Cloudflare Worker deployment (`wrangler deploy`) in your own Cloudflare account — no external hosting platform is involved. Secrets (`OPENAI_API_KEY`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET`, `PYPSX_API_KEY_ID`, `PYPSX_API_SECRET_KEY`, `PYPSX_OWNER_EMAIL`) are set with `wrangler secret put <NAME>`, never committed. Non-secret config (`ALLOWED_EMAILS`, `GOOGLE_CLIENT_ID`) lives in `wrangler.jsonc`'s `vars`.
- API requests require a signed-in Google account (any verified account by default; set `ALLOWED_EMAILS` to a comma-separated list to restrict sign-in again); writes also require same-origin requests. Per-user data is isolated with revision checks to reject concurrent stale saves.
- The automatic PSX refresh runs as a second, independent Cloudflare Worker (`workers/quote-refresh/`) on its own Cron Trigger schedule, sharing the same D1 database. Deploy it once with `npm run quote-refresh:deploy`; it writes to a shared `quote_refreshes` cache table that every user's portfolio read merges in, so it never touches per-user save/revision state.
- `quote_refreshes` is the single shared quote cache (`lib/quote-cache.ts`). The cron, "Refresh PSX prices" (`/api/quotes`) and the market pulse (`/api/market-summary`) all read it first and only fetch tickers that are stale (older than 3 minutes while PSX is open; fetched before the last close while it is shut), within a per-request PSX fetch budget that stays under the Cloudflare Workers subrequest cap. A ticker whose fetch fails or is over budget is served from cache and reported as stale. Portfolio reads merge the cache newest-wins, so an older cron row never replaces a newer saved or manual quote.
- PSX has removed its bulk `/market-watch`, `/timeseries/int/*` and `/performers` pages (they return 404). PSX also drops requests from Cloudflare's network (Workers get `520` on every page except the homepage), so live prices are scraped from outside Cloudflare: `.github/workflows/psx-quotes.yml` runs `scripts/psx-quote-scrape.mjs` every 5 minutes during PKT trading hours. One request to `/indices/ALLSHR` prices every All-Share stock (held tickers missing from it, e.g. ETFs, fall back to their company page) and the rows are upserted into `quote_refreshes` through the D1 REST API. The workflow runs in the `prod` GitHub environment and needs its environment secrets `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_API_TOKEN` (a token with D1 edit permission); keep `prod` free of required reviewers or wait timers so scheduled runs aren't held for approval. The Workers still try PSX themselves when the cache is older than 10 minutes, but stop at the first `403`/`52x`.
- The optional pyPSX stream accepts only a free paper-account key beginning with `PK_`. `PYPSX_OWNER_EMAIL` must exactly match the signed-in Google account that may use it. The server opens the provider WebSocket and filters messages to that account's saved shortlist; credentials are never returned to browser code. Add the same three values to `.dev.vars` for local verification.
